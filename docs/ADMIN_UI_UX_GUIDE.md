# Kiro Console 后台 UI / UX 设计手册

版本：1.0
适用范围：`admin-ui` 的管理后台、用户中心、登录页及后续新增的管理功能。
实现基准：React + TypeScript + Tailwind CSS + Radix UI + Lucide Icons。

本手册是项目的设计约定，不是第三方组件库的替代品。新增页面应先复用现有框架和组件，再补充业务内容；不得为单个页面另建一套顶栏、主题、按钮、表单或弹窗。

## 1. 设计原则

### 1.1 为管理工作服务

后台的核心是帮助用户快速判断状态、找到对象、完成操作、确认结果。视觉服务于信息，不以营销页的大渐变、大面积装饰、夸张动效或无意义插画为设计目标。

- 先呈现关键状态和主要任务，再展示辅助信息。
- 高频操作保持可见；低频、批量和危险操作按需出现。
- 用户应能回答：“现在是什么状态、我能做什么、做完会发生什么、失败如何处理”。
- 使用清晰的中文业务语言，避免只显示技术代码、内部字段或英文缩写；必要时辅以说明。
- 保持信息密度，但不得用缩小点击区域、竖排文字或压缩主要内容来换取密度。

### 1.2 一致、克制、可预期

- 相同含义使用相同颜色、组件、图标和文案。
- 相同操作在相同位置出现，例如主操作在区域右上、弹窗主操作在底部右侧。
- 主色只用于主要行动、当前选中及少量关键数据，不能整页泛用。
- 成功、警告、失败不能仅靠颜色区分，必须同时有文字或图标。
- 不让界面样式暗示错误权限：无权限的入口应隐藏或明确禁用并说明原因。

### 1.3 真实反馈与可恢复性

- 操作成功必须来自真实接口结果，不能点击后立即伪造成功。
- 加载、执行中、空数据、失败、禁用、无权限均是正式界面状态，必须设计。
- 删除、禁用、重置 Key、修改角色、调整余额等操作须清楚说明影响。
- 能撤销的操作优先提供撤销；不可撤销的操作必须二次确认。
- 刷新和重试不得丢失未提交的表单内容；后台任务可关闭弹窗继续运行时，必须明确说明。

## 2. 技术与组件地图

| 职责 | 唯一入口 / 复用组件 |
| --- | --- |
| 颜色、字体、主题与全局样式 | `admin-ui/src/index.css`、`admin-ui/tailwind.config.js` |
| 后台布局、权限导航、主题切换、退出 | `components/admin-shell.tsx` |
| 页面区块、统计卡、空状态、表格样式 | `components/page-elements.tsx` |
| 按钮 | `components/ui/button.tsx` |
| 卡片 | `components/ui/card.tsx` |
| 输入框、下拉框与文本域样式 | `components/ui/input.tsx` |
| 状态标签 | `components/ui/badge.tsx` |
| 弹窗 | `components/ui/dialog.tsx` |
| 进度 | `components/ui/progress.tsx` |
| 复选框与开关 | `components/ui/checkbox.tsx`、`components/ui/switch.tsx` |
| 全局轻提示 | `components/ui/sonner.tsx` |
| 通用样式合并 | `lib/utils.ts` 的 `cn()` |
| 图标 | `lucide-react`，默认 16–18px，风格统一为线性图标 |

开发新功能时：

1. 在 `AdminSection` 与 `sectionMeta` 注册模块，在 `lib/navigation.ts` 配置独立路径、导航与权限。
2. 使用 `AdminShell` 提供导航与页面标题。
3. 使用 `PageSection`、`MetricCard`、`Card` 组织内容。
4. 从 `components/ui/` 选择交互组件。
5. 只有现有组件无法表达业务时，才扩展其变体；不得复制一份近似实现。

## 3. 视觉设计规则

### 3.1 色彩

所有语义色从 `index.css` 的 HSL 变量读取，不在业务组件硬编码品牌色、背景色、边框色或浅色/深色变体。

| 语义 | 用途 | 使用限制 |
| --- | --- | --- |
| `background` | 页面底色 | 不作为输入框、弹窗的主表面 |
| `foreground` | 主要文字 | 标题、重要内容 |
| `card` / `card-foreground` | 卡片、输入、弹窗表面 | 用表面与页面背景区分层级 |
| `primary` | 主操作、当前导航、关键状态 | 每块区域原则上只有一个主操作 |
| `secondary` / `muted` | 次级表面、禁用、辅助分组 | 不承担重要正文 |
| `muted-foreground` | 描述、辅助文字、占位符 | 不用于关键警告或主要操作 |
| `accent` | 悬停、轻量选中背景 | 不代替主色行动按钮 |
| `success` | 可用、成功、正向余额 | 同时展示文本或图标 |
| `warning` | 待处理、额度风险、需注意状态 | 不与破坏性操作混用 |
| `destructive` | 删除、失败、严重异常 | 仅用于真实风险和错误 |
| `border` / `input` | 分隔、控件边界 | 不以高对比粗边框制造视觉噪声 |
| `sidebar` / `sidebar-border` | 导航表面与分隔 | 不与卡片背景混为随机新色 |

浅色基准：页面 `#F8F9FB` 附近、白色卡片、蓝紫主色。深色基准：低亮度蓝灰背景、略亮卡片、较亮蓝紫主色。准确值以 `index.css` 为准。

要求：

- 深浅主题使用相同语义，不是简单反色。
- 状态浅底使用对应语义色的低透明度背景与文字。
- 正文、按钮、输入框及状态标签保持足够对比度；验收时须实际检查深色模式。
- 不引入红绿蓝多套随机状态颜色，不用纯黑大面积遮罩，不通过高饱和渐变制造层级。

### 3.2 字体与数字

字体栈：系统无衬线字体优先，中文使用苹方、微软雅黑等系统字体。根节点和页面启用 `antialiased`。

| 内容 | 规则 |
| --- | --- |
| 页面标题 | 26–28px，字重 600，紧凑但不过度挤压字距 |
| 区块标题 | 16px，字重 600 |
| 卡片标题 | 14–16px，字重 600 |
| 正文与控件 | 14px，行高自然；说明文字行高约 24px |
| 辅助信息 | 12–13px，不用于长段关键操作说明 |
| 徽标与辅助标签 | 11–12px，字重 500 |
| 标题换行 | `text-balance` |
| 描述换行 | `text-pretty` |
| 长名称、邮箱、Key 前缀 | 单行省略并提供完整信息查看方式，不强制换行撑破布局 |
| 积分、Token、时间、次数、比例、ID | `tabular-nums`，避免数字更新导致布局抖动 |
| 密钥、哈希、ARN 等技术标识 | 等宽字体；默认脱敏，禁止在日志和列表暴露完整秘密 |

不要全局使用等宽字体，不要为了“高级感”把正文缩到 12px 以下。

### 3.3 间距与圆角

以 4px 为基础单位，主要间距采用 8 / 12 / 16 / 20 / 24 / 28 / 32px。

- 页面内容水平留白：手机 16px、较宽屏幕 24px、桌面 32px。
- 卡片内边距：20px；需要宽松表单或弹窗可用 24px。
- 统计卡、工具栏、列表之间的主要间距：16px。
- 大区块之间：24–28px。
- 普通按钮、输入、导航项：8px 圆角。
- 卡片：12px 圆角；弹窗：16px 圆角。
- 小标签：6px 圆角；头像、图标底：8–12px 圆角。
- 嵌套圆角遵循：**外圆角 ≈ 内圆角 + 内边距**，避免同半径同心不同圆。

### 3.4 边框、阴影与层级

- 普通卡片以细分隔线和极浅阴影建立层级，不使用厚重悬浮阴影。
- 弹窗、抽屉、下拉层允许明显但柔和的阴影及轻微背景模糊。
- 当前选中状态用浅主色背景、文字或细描边，不用厚重发光边框。
- 图层约定：内容层 → 吸顶工具栏 `z-20` → 桌面侧栏 `z-30` → 移动遮罩 `z-40` → 弹窗与移动导航 `z-50`。
- 不用不断增大 `z-index` 的方式解决局部层级问题，先检查组件结构。

## 4. 布局、路由与响应式

### 4.1 独立 URL

每个业务模块必须有独立、可分享的 URL，不能只保存在 React 内存状态中。路由定义统一放在 `lib/navigation.ts`，不得在多个组件中硬编码不同地址。

| 模块 | 路径 |
| --- | --- |
| 上游凭据 | `/admin/credentials` |
| 用户与额度 | `/admin/users` |
| 我的账户 | `/admin/overview` |
| 积分流水 | `/admin/transactions` |
| 安全与设置 | `/admin/settings` |

规则：

- 导航使用真实 `<a href>`，保留 Cmd/Ctrl 点击、新标签打开及复制链接能力。
- 普通点击通过 History API 切换模块，URL、导航高亮、页面标题与内容必须同步。
- 支持直接访问、刷新、浏览器前进后退；新增模块须同时实现服务端 SPA 回退。
- `/admin` 根据角色跳到默认首页，管理员进入凭据，普通用户进入我的账户。
- 未登录访问子路径时保留目标地址，登录成功后恢复；退出登录回 `/admin`。
- 无权限路径跳转 `/admin/overview`，不得仅隐藏菜单而仍展示敏感内容。
- 未知路径回退到角色默认首页；尾斜杠路径应兼容。
- URL 不得包含 API Key、Token、密码或完整敏感标识。

### 4.2 标准后台骨架

桌面 `lg` 及以上：

- 固定左侧栏，宽 232px；包含品牌、权限导航、当前用户与退出入口。
- 主区域左侧保留侧栏宽度，内容最大宽度 1600px。
- 顶部吸顶栏高 64px，展示当前模块与主题切换。
- 页面先有一个明确的 `h1` 和一句说明，然后才是统计、工具和内容。

手机与平板：

- 侧栏变为 280px 抽屉，使用 Radix Dialog 的焦点管理与 Escape 关闭。
- 页面标题、说明和主要内容不得被抽屉或工具栏遮挡。
- 工具栏允许换行；不得强制所有操作保持一行。
- 表单按钮在窄屏纵向排列，主要操作保持明显。

### 4.3 栅格

- 三个关键指标：`sm` 三列或按实际内容决定，手机单列。
- 凭据卡：中等屏幕两列、超宽屏三列；窄屏一列。
- 设置表单：桌面两列，手机一列。
- 双字段表单仅在标签和输入都能清晰展示时并排，否则改为单列。

### 4.4 溢出规则

- 页面容器使用 `overflow-x-clip`，但不得用它掩盖布局错误。
- 数据表只在自身容器内 `overflow-x-auto`，页面整体不得出现横向滚动条。
- 工具栏使用 `flex-wrap`，操作组有合理间距。
- 长邮箱、URL、用户名、ARN 使用 `min-w-0` 与 `truncate`，不得撑破卡片。
- 窄屏下不能用逐字竖排作为“响应式”方案。

## 5. 组件使用规范

### 5.1 按钮

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| `default` | 一个区域内的主要行动 | 创建用户、添加凭据 |
| `outline` | 可逆的次级行动、筛选、查询 | 查看额度、查询信息 |
| `secondary` | 低强调操作、后台任务入口 | 验活进度 |
| `ghost` | 工具图标、辅助操作、局部操作 | 刷新、主题、调整优先级 |
| `destructive` | 不可逆或高风险操作 | 删除、取消危险任务 |
| `link` | 语义明确的轻量导航 | 查看流水 |

规则：

- 统一使用 `Button`，不手写另一套按钮 CSS。
- 普通按钮、图标按钮最小高度 40px；图标按钮 40×40px。
- 图标和文字同时出现时图标约 16px，图标在文字左侧；纯图标必须有 `aria-label`，必要时加 `title`。
- 执行中显示加载图标与明确文字，并禁止重复提交。
- 禁用状态降低不透明度，同时通过 `title` 或邻近说明解释原因。
- 按压反馈使用 `active:scale-[0.96]`，不得使用夸张缩放；分散注意力的操作可使用 `static`。
- 主按钮在同一区域原则上只有一个；其余使用次级样式。

### 5.2 卡片与统计卡

- 卡片用于一组相关对象或任务，不用来包裹每一段文字。
- `MetricCard` 包含标签、主值、图标和可选说明；主值是最重要信息，不能把多个不相关指标塞进同一卡片。
- 正向健康状态可使用 `success`，当前活跃或重点值可使用 `accent`，普通统计保持 `default`。
- 统计卡只用于汇总；详细操作与状态应放在真实对象卡片或表格中。
- 卡片内部操作有主次：主要查看操作优先，危险操作使用小图标并附带说明。

### 5.3 表格

使用 `tableClass`、`tableHeadClass`、`tableRowClass`、`tableCellClass` 作为基础，再补充列对齐。

- 表头使用 12px 辅助文字；金额、Token、积分等数值右对齐。
- 用户名、状态等关键内容优先可见；操作靠右并保持可点击。
- 行悬停只作辅助，不能成为发现操作的唯一方式。
- 行内主操作可显示文字；多个次级操作可合并为图标，但必须可访问、可理解。
- 表格内只进行局部横向滚动，不裁切关键操作。
- 空数据使用 `EmptyState`，说明原因并提供下一步；搜索无结果与从未创建数据的文案不同。
- 分页显示当前页、总页数、总数；切换后保留合理筛选条件。
- 批量操作只在选中后出现，提供已选数量与取消选择。

### 5.4 表单

- 标签始终可见，不用 placeholder 代替 label。
- `Input`、`formControlClass`、`textareaClass` 分别用于输入、下拉、多行文本。
- 标签与控件间距 8px；字段组间距 16px；关联字段可组合，但不宜过度嵌套卡片。
- 必填项明确标记；格式要求、长度限制、默认值和影响在输入前可见。
- 数字字段限制合理范围与步长，金额、积分、优先级等须校验实际含义，不只检查是不是数字。
- 密钥、Token、密码使用适当的密码输入类型，粘贴流程不能破坏内容。
- 错误应贴近对应字段；提交失败显示可理解的服务端错误，不清空用户输入。
- 加载期间保留字段内容和当前步骤，不允许重复提交。
- 非必要的高级配置默认收起或靠后，不让首次使用者面对过多选项。

### 5.5 弹窗与抽屉

使用 `Dialog` 处理表单、详情、确认及任务结果，使用移动导航抽屉承载小屏导航。

- 标题说明“做什么”，描述说明“影响什么”，不只重复按钮名称。
- 宽度按内容选择：简单确认 / 详情默认宽度，复杂导入与长表单可用 `sm:max-w-2xl`。
- 高度最大为视口的 90%，长内容区域可滚动，标题与操作保持可达。
- 桌面底部操作为次操作在左、主操作在右；手机可纵向堆叠。
- 提供关闭按钮、Escape 关闭、焦点管理与清晰标题。
- 危险确认明确对象、数量与不可逆后果；按钮写“确认删除”，不使用含糊的“确定”。
- 执行危险批量任务时，显示进度、成功、失败及回滚状态。
- 能后台运行的任务提供“后台运行”；不能中断的任务不得用关闭按钮误导用户。

### 5.6 状态、加载、空与错误

每个异步模块至少实现：

| 状态 | 表现 |
| --- | --- |
| 首次加载 | 保留布局，使用 spinner 或骨架；不伪造空数据 |
| 局部刷新 | 保留已有内容，局部加载，不整页闪白 |
| 执行中 | 加载图标、明确动作文案、禁止重复操作 |
| 无数据 | `EmptyState`，解释原因并给出下一步 |
| 搜索无结果 | 保留搜索词和清除/调整入口 |
| 可恢复失败 | 说明原因并提供重试，不自动无限重试 |
| 无权限 | 隐藏入口或明确无权限说明，不能点击后才暴露 |
| 禁用 | 清晰标识，并解释限制及恢复方式 |
| 完成 | 轻提示或结果摘要，必要时更新对应数据缓存 |
| 后台执行 | 明确任务仍在运行，可重新打开查看进度 |

## 6. 后台信息架构与操作模式

### 6.1 导航与权限

固定模块顺序：运行概览 → 上游凭据 → 用量统计 → 用户与额度 → 我的账户 → 积分流水 → 安全与设置。

- 运行概览（`/admin/monitor`）仅管理员可见，集中展示实时 RPM、进行中请求、成功率、最近请求及凭据池统计；普通用户直接访问时回退到我的账户。
- 上游凭据对超级管理员和普通管理员可见；普通用户不显示。页面只保留凭据列表、搜索筛选及管理操作，不重复展示实时监控、最近请求或统计卡。
- 普通管理员可查看、搜索及登记凭据，只能管理本人及后代代理登记的凭据；其他分支的凭据显示“仅查看”。
- 超管核心配置：Region、Kiro 客户端版本、默认端点、负载均衡、TLS 后端、非流式 Thinking 提取与全局代理。保存后原子写盘并热重载，新请求使用新配置，存量流式响应不受影响；密钥不回显，代理认证默认保留。
- 用户与额度对管理员及以上可见，普通用户不显示。
- 普通用户进入“我的账户”，管理角色默认进入有权限的工作台。
- 当前导航同时使用浅色背景、主色文字与 `aria-current="page"`。
- 当前用户、角色和退出入口位置固定，不在不同模块改变含义。
- 角色或权限变化后，导航与内容使用最新账户数据，不能长期保留旧权限界面。

### 6.2 凭据管理

- 首先显示总数、可用数、当前活跃和分配模式，再显示对象列表。统计卡与实时请求统一放在「运行概览」，不在凭据管理页重复展示。
- 「运行概览」的实时请求卡展示最近 60 秒 RPM、进行中请求、最近完成成功率及最近请求；每 5 秒局部刷新，并展示最后更新时间和刷新失败状态。进行中与已完成分别标识，不显示提示词或密钥。
- 实时数据是当前实例的短期内存快照，不宣称为持久化历史审计；切换实例后从空数据开始，历史消耗由「用量统计」提供。
- 提供邮箱、ID、端点、登记人关键词搜索，以及状态和管理权限筛选；搜索作用于完整列表而非当前页，结果计数、分页和空状态同步更新。
- 凭据卡展示登记人和当前用户是否可管理；仅查看项保留额度查询，隐藏或禁用启停、编辑、刷新、删除及批量操作。
- 凭据支持卡片和列表两种视图，切换按钮使用 `aria-pressed`，选择保存在当前浏览器。列表保留搜索、筛选、分页、选择、启停、优先级、额度查询、刷新、重置和删除，不能因切换视图放宽权限。窄屏只允许表格容器内部横向滚动，不允许整页溢出。
- 默认展示高频查看操作；刷新、重置失败、调整优先级和删除用图标辅助。
- 批量操作需先选择，明确选中数量和禁止条件。
- 禁用是删除前置条件，禁用按钮和删除原因必须可理解。
- 查询余额、刷新 Token、验活是不同任务，文案不可混用。

### 6.3 用量统计

- 所有角色均可访问；超管查看全部，普通管理员仅本人及后代代理，普通用户仅本人。普通用户不显示用户筛选器。
- 支持开始和结束日期、今天、昨天、近 7 天、用户筛选和按日期、用户、模型、请求状态聚合。日期以北京时间（UTC+8）自然日为准，结束日期包含当天，不能只看 UTC 日期。
- 总 Token、实际消耗积分、请求数、失败数和独立活跃用户统计完整筛选范围，不能用当前页或最多 200 条分组代替全局汇总。
- 积分按实际结算消费计算，不重复累计预扣和返还；失败请求保留次数，不计伪造消费；进行中的请求不进入历史用量。
- 表格显示输入/输出 Token、积分、调用/失败次数、总耗时和首字耗时；提供 Token 占比、空数据、失败重试及局部刷新状态。

### 6.4 用户与额度

- 提供搜索、创建用户、角色、状态、余额、消费及行内操作。
- 普通管理员可创建直属下级代理，并管理本人及后代代理的账户；不得显示或修改其他管理员分支的账户。
- 创建后完整 Key 只展示一次，必须明确提醒保存。
- 充值与扣减使用同一个“调整积分”任务：正数充值、负数扣减，显示当前余额与备注。
- 重置 Key 明确提示旧 Key 立即失效；禁用账户需提示业务影响。
- 普通用户仅看到自己的余额、流水和安全设置，不能伪造管理视图。

### 6.5 账户、流水与设置

- 账户优先展示可用积分、累计消费、Token 汇总和当前计费标准。
- 默认展示“调用日志”，每次请求只占一行；消费成功显示实际负向积分变动，失败显示 `0` 和错误状态。
- 调用日志包含状态、HTTP 状态码、模型、接口、输入/输出 Token、总耗时和首字时间；点击详情按钮可查看请求 ID、具体错误及积分结算过程。
- 消费详情的积分变动按“调用前余额 → 预扣 → 返还 → 实际消费 → 结算后余额”排列，预扣与返还不在列表拆成多行。
- “充值调整”独立展示开户初始积分和管理员调整，不与 API 调用混排。
- 不保存完整提示词、回复正文或逐分片日志；错误摘要最多 2 KB，不记录 API Key、密码和会话凭据。
- 历史流水按零实际消费识别失败，未保存的错误、耗时或预扣关联必须明确标为未记录，不得伪造。
- 修改密码、重置 Key、修改计费单价需说明后果并处理登录状态与缓存刷新。

## 7. 文案与错误规范

- 使用“创建用户”“添加凭据”“调整积分”“查看额度”等明确动词。
- 名称保持统一：使用“用户与额度”“积分流水”“上游凭据”“安全与设置”。
- 不在正常 UI 使用表情符号代替状态图标，不使用 `✓`、`✗`、`⚠` 充当唯一反馈。
- 错误先告诉用户发生了什么，再告诉如何处理；技术详情作为辅助，不直接倾倒堆栈。
- 示例：
  - “余额不足，请先调整积分后再试。”
  - “Token 刷新失败，请检查凭据是否仍有效。”
  - “删除后无法恢复。仅可删除已禁用的凭据。”
  - “加载失败，请检查网络后重试。”
- 加载文案用“创建中…”“导入中…”“正在查询”，不使用无上下文的“请稍候”。

## 8. 可访问性与操作安全

- 页面只有一个主 `h1`，区块标题按语义层级排列。
- 所有输入有 `label`，所有纯图标按钮有可访问名称。
- 所有功能可键盘操作，焦点状态清晰；弹窗打开后管理焦点，Escape 可退出。
- 任何可点击控件最小命中区 40×40px；小复选框和开关可通过伪元素扩大命中区，但不得重叠相邻控件。
- 不用 `div onClick` 模拟按钮，使用 `button` 或合适的 Radix 组件。
- 图片如有业务用途，使用浅色模式 `rgba(0,0,0,0.1)`、深色模式 `rgba(255,255,255,0.1)` 的细描边，并提供替代文本。
- 敏感信息不在表格、日志、Toast、URL 参数或截图示例中完整暴露。
- 认证仅通过 HTTPS 进行；普通 HTTP 环境不得提示“安全保存成功”或伪造剪贴板成功。

## 9. 动效与性能

- 动效说明状态变化，不用于拖延操作。
- 普通交互使用 150–200ms 的颜色、透明度或位移过渡，且可以中途打断。
- 弹窗使用轻微淡入与缩放，退出比进入更克制；不让整个页面反复大幅滑动。
- 图标按钮悬停以颜色为主，按压以 `0.96` 缩放为主。
- 不使用 `transition: all`，明确指定 `background-color`、`border-color`、`color`、`opacity`、`transform` 等属性。
- `will-change` 仅在确认有合成层性能问题时用于 transform / opacity / filter。
- 支持 `prefers-reduced-motion`，减少或取消非必要动画。
- 首屏不播放多余入场动画，避免后台数据刷新导致整页闪动。
- 数据更新保持原布局，局部刷新优先于整页重新挂载。

## 10. 修改与扩展规则

### 10.1 可以做

- 基于语义变量增加经过评审的组件变体。
- 使用 `cn()` 合并布局、宽度、对齐和响应式类名。
- 为复杂业务封装可复用的领域组件，并纳入统一设计规则。
- 在不改变操作含义的前提下优化信息顺序、空状态和反馈。

### 10.2 不可以做

- 为某页面单独引入不同主题的 UI 框架或另一套设计变量。
- 在业务组件中硬编码新的主色、灰色、状态色、阴影和圆角。
- 复制 `Button`、`Card`、`Dialog` 等基础组件后只改少量样式。
- 通过缩小文字、缩小点击区或页面横向滚动解决空间不足。
- 未经评审替换技术栈、引入大型依赖，或加入与现有风格冲突的图标库。
- 为“好看”隐藏关键状态、权限限制、失败原因或危险后果。
- 用前端权限隐藏替代后端鉴权。

### 10.3 设计变更流程

1. 说明当前用户任务和要解决的问题，先评估信息结构与交互，不先换颜色。
2. 列出可复用组件和缺失变体，优先扩展共享组件。
3. 同时给出浅色、深色、桌面、手机、加载、空、错误、禁用状态。
4. 检查危险操作、权限、敏感信息及接口失败路径。
5. 更新相关共享组件和本手册，确保规则与实现一致。
6. 通过构建与真实页面验收，不以静态截图或单纯编译通过代替交互验证。
